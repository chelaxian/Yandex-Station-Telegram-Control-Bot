# Проверка VPN и сообщения о сбросе — 04.11.2026

## Область и результат

Пользователь подтвердил, что проблемный установщик был **2.7**. Текст «Шаг 1/3», «Быстрое авто-сканирование Wi-Fi сети» и диапазон `.1–254` совпадают с `bot/setup.py` в исторической ветке [alfa](https://github.com/chelaxian/Yandex-Station-Telegram-Control-Bot/blob/alfa/bot/setup.py). Проверенный исторический commit: `ea1d459e0fe38c6da2cf2cfd2580e6cf8fd91a20`. Точное содержимое запущенного сторонним пользователем архива не получено; оно могло отличаться.

В 2.7 локальный IP определяется UDP `connect` к `8.8.8.8`, затем из него строится /24. Это выбор исходящего маршрута, который может принадлежать VPN. Ошибка выбора подсети подтверждается исходниками. Старый установщик не исправляется и не распространяется заново: 2.7 хранится только в `alfa`, из актуального `main` удалены её код и материалы.

Новый установщик `stationbot.setup` **запрашивает IP вручную**. Он не использует интернет-маршрут для определения LAN. `/discover` — отдельное действие владельца с явно заданной подсетью, без автоматического выбора интерфейса. Внесена защита от fake-IP: принимаются только RFC1918 `10/8`, `172.16/12`, `192.168/16`; `198.18/15`, link-local, loopback и другие специальные диапазоны отклоняются до подключения. Python `is_private` шире RFC1918, поэтому прежней проверки было недостаточно. VPN с RFC1918-адресом нельзя отличить от LAN только по адресу; маршруты/kill switch установщик не меняет.

## Новый код: пути записи и привилегии

Статически проверены `install.cmd`, `install.ps1`, `install.sh`, `deploy/bootstrap.py`, `stationbot.setup`, `provision`, `supervisor`, `features`, `assets` и HTTP-клиент. Для расширений LUNA просмотрены `src/owner.rs` и `src/audio_jobs.rs` закреплённого [0f2393e](https://github.com/chelaxian/luna/tree/0f2393e4d613472c79755b358abc3047a9466963). Это проверка исходников, не воспроизведение инцидента на чужой колонке и не полный аудит firmware/backend всех моделей.

| Путь | Что выполняется | Связь со сбросом |
|---|---|---|
| Host installer | Зависимости ОС хоста, venv, приватная конфигурация, служба/задача хоста | Команд factory reset колонки нет; systemd restart относится к боту на хосте |
| ADB probe | UID, архитектура, board, firmware; квалификация до установки | Чтение идентичности, без reboot/OTA |
| Provision | Файлы только managed `/data/local/stationbot-luna`, собственные `/tmp/stationbot-luna-*`, SHA, резерв предыдущей LUNA | Не удаляет Wi-Fi/аккаунт/Quasar data, не пишет MTD, не меняет rootfs/vendor boot hooks |
| Stop/recover | Остановка только процесса с точным executable managed LUNA; восстановление локального forward | Нет `killall`, остановки штатного maind, reboot или сброса общего ADB server |
| `/cleanup` | Удаление собственных `.pending-*` прикладного assets-каталога на хосте | Не очищает `/tmp/*` и пользовательские каталоги колонки |
| Backup/restore | ZIP прикладных данных; сохраняется предыдущая копия | Не восстанавливает заводские настройки и не пишет образ в раздел |
| `/firmware` | Create-only файл через owner/files, SHA; `flashed=false` | Сам по себе не прошивает колонку |
| Терминал / пользовательские .sh / пакеты | Явные привилегированные операции с проверками роли и настроек | **Могут выполнять опасные команды, если их передал владелец или разрешённый пакет. Это не sandbox** |

В автоматическом сценарии новой установки не обнаружена команда сброса, форматирования, удаления учётной записи/Wi-Fi или запуска recovery. Это не гарантия отсутствия косвенного сбоя: заполнение хранилища, сбой питания, существующая прошивка/моды, backend LUNA и явно запущенные root-команды требуют отдельного анализа. Проверка места перед переносом бинарника не является гарантией исправности всей Flash.

## Историческая 2.7: что найдено

В проверенном `setup.py` нет явной команды factory reset или reboot. Установка, однако, копирует скрипты/звуки в `/data/opt` либо `/bkupgrade/data/opt`, задаёт громкость 85%, проигрывает звук, останавливает RGB и удаляет несколько RGB-файлов. Поддержка модели и свободное место перед этим полноценно не проверяются. В автономном варианте создаётся `opt/autostart.sh`; сам файл не доказывает рабочую регистрацию автозапуска.

В старом `bot.py` есть root-shell, исполнение своих функций/скриптов, reboot по команде помощника и по кнопке. Очистка кэша выполняет широкое `rm -rf /tmp/* /data/tmp/*` и удаление старых логов; это способно нарушить работу чужих процессов, но не доказывает сброс привязки. Legacy display helper также пишет настройки часов Quasar и использует bind mount для датчика освещённости. Сохранение образа в 2.7 само по себе не пишет MTD: опасные flash-команды выводятся как инструкция для ручного терминала.

Наличие этих возможностей не означает, что они были вызваны при инциденте. Статический просмотр не установил причинную связь между установкой и последующим режимом настройки. Сохранение root/ADB после reboot также само по себе не различает потерю привязки, проблемы пользовательского раздела, сетевой сбой или другое состояние firmware.

## Что нужно для расследования конкретной колонки

Сначала сохранить данные, не выполнять повторную установку, очистку, отвязку или reset ради диагностики. Нужны модель/board, полная firmware, SHA-256 использованного архива, выбранный режим установки, время и последовательность действий до reboot, нажатые команды/кнопки, обезличенные сообщения загрузки/Quasar и состояние/свободное место пользовательского раздела. Сопоставить firmware до/после, если прежняя версия известна. Исследование конкретных логов — только с согласия владельца, без публикации tokens, identity/key blobs и личных разговоров.

Устройства владельца проекта не сбрасывались и не перезагружались для этой проверки. Регрессионные тесты проверяют отклонение специальных диапазонов до ADB/сокетов и сохранение работы ограниченного явного LAN-сканирования; они не подменяют диагностику чужого устройства или испытания VPN kill switch.
