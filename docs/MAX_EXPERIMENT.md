# Станция Макс: экспериментальная интеграция

Станция Макс YNDX-0008 и Станция 2 используют пересекающееся имя платформы Android. Установщик не должен считать совпадение этого имени подтверждением модели: существующий профиль Станции 2 для Макса не подходит. Поддержка автоматической установки на Макс пока не включена.

В отдельном [черновом PR LUNA](https://github.com/nyakokitsu/luna/pull/33) исследуется backend кольца. По предоставленным владельцем данным кольцо — framebuffer 24×1, 24 bpp, а матрица — 25×16, 24 bpp. На прошивке владельца [подтверждены](https://github.com/chelaxian/Yandex-Station-Telegram-Control-Bot/issues/2#issuecomment-6764253141) цвета BGR и возврат штатной индикации после выключения кольца. Длительное сосуществование с прошивкой не квалифицировано: при первом тесте наблюдалось однократное необъяснённое обнуление. Экран, звук, громкость и микрофон на Максе также не квалифицированы.

Клиент бота использует `expected_model` и возможности `/api/device`. После проверки экспериментального LUNA можно отдельно проверить подключение бота через защищённый локальный туннель с `expected_model = "yandexstation_max"`. Доступность пункта меню не доказывает работу оборудования; результаты следует записывать отдельно по каждой функции и версии.

Запуск другого экземпляра LUNA может остановить существующий из-за общего lock. Перед экспериментом владелец должен проверить наличие работающей LUNA и сохранить её настройки; не запускать тест параллельно с ней. Никаких операций с прошивкой, OTA или сбросом для этой проверки не требуется.

По [отчёту владельца](https://github.com/chelaxian/Yandex-Station-Telegram-Control-Bot/issues/2#issuecomment-6764374599), у fb4 формат `rgba 8/16,8/8,8/0,0/0`: предположительный порядок байтов BGR на матрице ещё не подтверждён визуально. Утилиты tinyalsa и alsa не найдены в PATH; наличие `/dev/snd` не подтверждает доступное воспроизведение или запись. На его розничной прошивке ADB работает без root, `su` отсутствует; существующий доступ root предоставляется отдельно по SSH-ключу. Текущий ADB-установщик не поддерживает этот транспорт и не должен обходить проверку UID.

Для изучения альтернативного транспорта есть отдельная read-only проверка `python -m stationbot.max_ssh_probe --host IP --user USER --port PORT`. Она требует заранее проверенный ключ хоста и действующий ключ SSH, проверяет UID и признаки framebuffer и ничего не устанавливает. Проверка пока не встроена в установщик или восстановление; она проверена на имитации SSH, результат на реальном устройстве ожидается. `GET /api/clock` в эксперименте сообщает наличие backend, но при постоянно занятой штатными часами матрице команда записи отклоняется; владелец подтвердил, что framebuffer при этом не меняется.

После подтверждения этой проверки следующим безопасным шагом является `python -m stationbot.max_audio_probe --host IP --user USER --port PORT`. Проба повторяет идентификацию root/железа, затем читает только метаданные ALSA из `/proc/asound`, имена PCM-устройств, статус Quasar-сервисов `maind`/`aliced`/`yio_audio` и наличие их конфигурационных файлов. Она не открывает PCM, не меняет микшер, не воспроизводит и не записывает звук; результат позволяет лишь выбрать, какой audio backend можно безопасно квалифицировать дальше. Локальный исследовательский дамп прошивки fw 5000000896 показывает карточку AML-AUGESOUND, playback PCM 00-00/00-02, capture PCM 00-01 и штатный Quasar audio-стек; его vendor audio policy объявляет основной вывод 48 кГц stereo на Speaker и встроенный микрофон PCM16 с 16 каналами на 16/48 кГц. Это статическая ссылка, а не подтверждение текущего устройства.

Внутренний контракт гибридного транспорта также остаётся проверочным: ADB и SSH должны указывать на один LAN-адрес, ADB допускается только с UID 2000/aarch64, root-команды — только через строгий SSH, а локальный forward открывается лишь после обеих проверок. В контракте пока намеренно нет загрузки файлов, установки и произвольных удалённых команд.
